## External configuration required before a real provider test

These steps cannot be completed from GitHub alone because they require access to external accounts and secret material.

### AWS Amplify / runtime

- [ ] Connect/deploy the `dev` branch in AWS Amplify using Node.js 22.
- [ ] Set `NEXT_PUBLIC_SITE_URL` to the exact HTTPS dev URL.
- [ ] Create encrypted SSM SecureString `/before-you-trust/dev/runtime`.
- [ ] Put search/email/runtime secrets only inside that SecureString.
- [ ] Set only `RUNTIME_SECRETS_PARAMETER=/before-you-trust/dev/runtime` in normal Amplify configuration.
- [ ] Create/attach a least-privilege Amplify SSR Compute role with only `ssm:GetParameter`, `dynamodb:UpdateItem`, and optional KMS decrypt if a customer-managed key is used.

### Search provider

- [ ] Configure at least one real provider: Tavily and/or Brave Search.
- [ ] Keep `SEARCH_PROVIDER=auto` unless intentionally testing a single provider.

### Photo matching

- [ ] If photo matching will be included in the real test, enable Google Cloud Vision Web Detection and configure a server-side restricted API key.

### Brevo transactional email

- [ ] Configure a verified sender/domain.
- [ ] Configure `BREVO_API_KEY`, `BREVO_FROM_EMAIL`, `BREVO_FROM_NAME`, `OWNER_NOTIFICATION_EMAIL`, `REPEAT_ALERT_EMAIL_TO`, and `REPORT_REQUEST_NOTIFICATION_EMAIL` in encrypted runtime config.
- [ ] Keep story/report delivery transactional; do not add visitors to marketing contacts.
- [ ] Prefer transactional open/click tracking off for this MVP unless separately justified.

### Repeat-search privacy signal

- [ ] Create DynamoDB table `before-you-trust-search-signals` with partition key `subjectKey` (String), on-demand billing and TTL attribute `expiresAt`.
- [ ] Generate a random `SEARCH_FINGERPRINT_SECRET` of at least 32 characters.
- [ ] Keep `REPEAT_ALERT_INCLUDE_NAME=false`.

### Support / analytics / launch-hardening

- [ ] Add the real `NEXT_PUBLIC_BUY_ME_A_COFFEE_URL` when the public support page exists.
- [ ] GTM/GA4 is optional for the real search test; if enabled, verify no Google analytics request occurs before opt-in.

- [ ] Add WAF/rate-based protection before meaningful public traffic.

- [ ] Have Privacy/Terms/Acceptable Use reviewed before meaningful public scale.

## Gate for the first real end-to-end test

Do **not** test a real subject until these minimum items are green:

1. `dev` is deployed over HTTPS.
2. At least one real web-search provider is configured.
3. Brevo is configured if report/story email is part of the test.
4. Google Vision is configured if photo matching is part of the test.
5. Runtime secrets are in encrypted SSM, not GitHub or normal public environment variables.
6. DynamoDB fingerprint storage is configured if repeat-search monitoring is enabled.
7. `REPEAT_ALERT_INCLUDE_NAME=false`.
8. The test subject has consented. The founder/self-test is appropriate for the first real run.

See `MANUAL_SETUP.md` for exact account-level instructions.
