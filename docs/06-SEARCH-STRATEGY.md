# Search Strategy

## Stage 1 — identity discovery
Start neutral. Establish who the person is before looking for negative information.

Example query families:
- `"Full Name"`
- `"Full Name" city`
- `"Full Name" employer`
- `"Full Name" username`
- `"Full Name" LinkedIn`
- `"Full Name" GitHub`
- `"Full Name" interview`
- `"Full Name" conference`
- `"Full Name" university`
- `"Full Name" filetype:pdf`

## Stage 2 — selected identity expansion
After the user confirms the person:
- known employers
- organizations
- domains
- publications
- company directorships where public
- qualifications/licenses where public
- credible news mentions
- official/regulatory sources

## Stage 3 — claim verification
For each material claim:
1. Extract the claim.
2. Search specifically for corroborating and conflicting evidence.
3. Prefer primary/official sources.
4. Mark the result as Verified, Corroborated, Unverified, or Conflicting.

## Stage 4 — risk-relevant searches
Only after identity is established. Avoid a system that starts by searching accusations against every name.

Potential contextual searches may include terms relevant to the user's relationship/context, but findings must be source-ranked and allegations must never be converted into facts.

## Source hierarchy
1. Government / regulator / court / official professional registry
2. Organization or employer primary source
3. Reputable journalism
4. Academic/professional publications
5. Established directories/databases
6. Self-published profiles
7. Forums/social posts

Lower-quality sources can be discovery leads but should not independently support strong conclusions.

## Search-quality principle
The system must optimize for useful, correctly matched sources—not for producing a dramatic report. An honest sparse result is preferable to a large low-quality result set.
